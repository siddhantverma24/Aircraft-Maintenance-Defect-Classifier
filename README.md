# ✈️ Aircraft Maintenance Defect Classifier (NLP)

Classifies free-text aircraft maintenance defect write-ups into **ATA chapters**
and extracts key entities (components, part numbers, positions, measurements…),
served through an interactive **Streamlit** web app.

> *"#2 EGT exceeded limits during climb, thermocouple P/N 2043M41P01 replaced"* → **ATA 72 – Engine** (89%)

## Why it matters
Airlines record thousands of defects per month as free text in technical logs.
Each must be coded to an ATA chapter for reliability analysis, repeat-defect
tracking and regulatory reporting. Manual coding is slow and inconsistent.
This project automates it and flags ambiguous entries for human review.

## Dataset (synthetic - please note)
The dataset is **synthetic**, generated by `generate_data.py` from templates that
mimic technical-log language across **16 ATA chapters** (3,000 write-ups):
abbreviations (hyd, eng, L/H, IAW AMM), part/serial numbers, positions,
measurements, typos, ALL-CAPS entries, and ~18% deliberately *vague* entries
("valve leaking in wheel well") whose only clue is the aircraft zone.
Real-world data (e.g. FAA Service Difficulty Reports, which carry JASC/ATA codes)
is the natural next step. Results on synthetic data are optimistic compared
with real logs.

Split: 70% train / 15% validation / 15% test, stratified by chapter.

## Models
| | Approach |
|---|---|
| **Baseline** | TF-IDF (word 1-2 grams + character 2-5 grams) → Linear SVM (calibrated for probabilities) |
| **Transformer** | DistilBERT (`distilbert-base-uncased`) fine-tuned, 4 epochs, mixed precision on GPU |
| **Entities** | Rule-based NER: ATA component lexicon + regular expressions, longest-match resolution |
| **Explainability** | Leave-one-word-out occlusion: shows which words drove each prediction |

## Results (test set, 450 write-ups)
| Model | Accuracy | Macro-F1 |
|---|---|---|

## Setup (Windows, either laptop)

```bash
git clone <your-repo-url>
cd ata-classifier
python -m venv venv
venv\Scripts\activate          # Mac/Linux: source venv/bin/activate
```

**1. Install PyTorch for your GPU first**

RTX 5050 (and also works for GTX 1650):
```bash
pip install torch --index-url https://download.pytorch.org/whl/cu128
```
The RTX 50-series needs a CUDA 12.8 build; older PyTorch builds won't see the GPU.
If the GPU isn't detected, update the NVIDIA driver to a recent version.
No GPU? `pip install torch` works on CPU (training takes ~30–60 min).

Check it:
```bash
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

**2. Install the rest**
```bash
pip install -r requirements.txt
```

**3. Build everything (data → baseline → DistilBERT)**
```bash
python run_all.py
```
First run downloads DistilBERT (~260 MB). Training: ~5–10 min on RTX 5050,
~15–25 min on GTX 1650. Use `python run_all.py --skip-bert` for a quick baseline-only run.

**4. Launch the demo**
```bash
streamlit run app.py
```

> Trained models are *not* in the repo (DistilBERT is too large for GitHub).
> Just run step 3 on each laptop, or copy the `models/` folder across.

## Project structure
```
generate_data.py   synthetic dataset generator (16 ATA chapters)
common.py          shared split / metrics / confusion-matrix code
train_baseline.py  TF-IDF + SVM
train_bert.py      DistilBERT fine-tuning (auto GPU/CPU, auto batch size)
ner.py             rule-based entity extraction
predict.py         model loading, top-k prediction, occlusion explanations
app.py             Streamlit demo (single / batch / model comparison)
run_all.py         one-command rebuild
reports/           metrics, classification reports, confusion matrices
```

## Limitations
- Synthetic data: vocabulary is limited to the generator's templates; real logs are messier.
- Rule-based NER only knows components in its lexicon.
- Chapter-level only (e.g. 72), not sub-chapter (72-30).
